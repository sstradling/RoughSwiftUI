# Changelog

## Unreleased

- `.strokeMiterLimit(_:)` sets the CoreGraphics miter limit for `.strokeJoin(.miter)`. The default is `10`, matching CoreGraphics, and values below `1` clamp to `1`. `RoughView` and `RoughText` both have the modifier. `RoughText` also has `.strokeCap(_:)` and `.strokeJoin(_:)` so a text outline can select the join that limit applies to. The value lives on `Options.strokeMiterLimit`, is included in `Options.cacheHash`, and is applied by every native `StrokeStyle`, including animation frames. `NativeStrokeOutline` builds a filled outline of a uniform-width stroke with the same caps, joins, and miter limit, for clipping or compositing. Taper, calligraphy, and width jitter still use `StrokeToFillConverter`.
- Native outlines use continuous cubic Beziers by default (`Options.strokeContinuity` is `.continuous`). A circle or ellipse is four cubics per pass. An arc uses the analytical handle length and splits on quadrant boundaries. A rectangle, polygon, linear path, rounded rectangle, or egg is one subpath per pass, with each corner jittered once and shared by the adjacent segments. `curve`, SVG paths, and text are unchanged. `.strokeContinuity(.legacy)` keeps the sampled rough.js outlines. The mode is part of `Options.cacheHash` and the drawing cache key. `RoughText` has the same modifier.
- Scribble fills are clipped to SVG paths and native polygons, so a concave outline cannot leak across notches between ray intersections. Rectangles, circles, and ellipses stay unclipped.
- The sample app is `Example/SketchyDemo`. The Xcode project, target, scheme, and app entry point are `SketchyDemoApp`, and the bundle id is `com.sstradling.SketchyDemo`. It links the local package product `Sketchy` and targets iOS 18. The previous app was `Example/RoughSwiftApp`. The demo adds primitive drawables, fill and dash options, text alignment and offsets, `AnimationConfig` with `AnimatedRoughView`, and the drawing added since 1.2: `fillPadding`, `fillOffset`, a variable marker, `.widthStops`, `.opacityProfile`, `.fillStyle(.watercolor)`, the watercolor brush, and SVG arcs.
- `BrushProfile.watercolor(pigment:wetness:edgeDarkening:layers:variation:bleed:seed:)` and `.watercolor` paint a wash along the outline. The body stays lighter. One broken rim is darker and fades along the stroke. The ribbon's base width stays even and both tips taper gradually. `bleed` and `variation` wobble each edge independently, with a low-frequency drift, a finer ripple, and an occasional outward bleed. Glaze layers do not share that edge. Specks are scattered from a seed. Glazes are ordinary translucent fills, so a crossing goes darker. `bleed` wanders the edge. It does not blur. The same seed repeats the wash. `WatercolorStyle.defaultSeed` (`1`) yields to `Options.seed`. A watercolor brush shares its style with `.fillStyle(.watercolor)`.

## [1.3.0] - 2026-11-03

- Strokes can change opacity along their length. `OpacityProfile` is `.uniform` (the default, multiplier 1), `.values` (evenly spaced samples), `.stops` (`OpacityStop` positions in 0...1), or `.noise` (a seeded wobble between a minimum and a maximum). The profile multiplies `strokeOpacity`. A curve that changes along the stroke is painted into one mask: each piece is opaque gray at that opacity, `luminanceToAlpha` turns the gray into coverage, and the stroke colour tints the mask. Overlaps replace instead of adding, so segment joins do not go dark. `.uniform` keeps the existing stroke path. A watercolor fill does not use this mask.
- `.fillStyle(.watercolor)` clips a wash to the same region as a solid fill, so `fillPadding` and `fillOffset` apply. Layers are translucent glazes, the dried edge is an uneven darker band, and blooms are irregular puddles. `WatercolorStyle.defaultSeed` (`1`) yields to `Options.seed`. Sketch fills such as hachure stay as they are.
- SVG paths draw elliptical arcs (`A` / `a`). Each arc uses the SVG endpoint-to-center conversion and becomes cubic segments of at most 90°, then picks up the same roughness as an authored curve. Radii that cannot reach the endpoint scale up together. A zero radius is a straight line. Identical endpoints are skipped. A relative `a` moves only the endpoint. After `Z`, the next relative command starts at the subpath point.
- Open strokes can set absolute widths in points with `.widthStops([(0, 4), (0.1, 8), (0.9, 8), (1, 4)])` or `ThicknessProfile.stops([WidthStop])`. Positions run from 0 to 1, are sorted and clamped, and interpolate linearly. The width holds before the first stop and after the last. An empty list stays an even `strokeWidth`. A non-empty list ignores `strokeWidth`. `.custom([CGFloat])` is unchanged: those values stay evenly spaced multipliers. With `strokeWidth` 8, `.custom([0.5, 1, 1, 1, 1, 1, 1, 1, 1, 1, 0.5])` matches the 4pt / 8pt / 4pt stops above. `.widthStops` replaces `.variable`, so marker noise is not multiplied on top; the brush tip still scales the stop width by direction. An open stopped stroke fills with the winding rule so the two rough passes union into one mark. The round end cap bulges out along the stroke; it no longer folds back between the corners and leaves a notch. Closed contours still drop stops and variable width and draw an even `strokeWidth`.
- Marker strokes can change width along an open path. `BrushProfile.marker(variation:minimum:maximum:taperStart:taperEnd:pressure:seed:frequency:)` keeps the flat tip, butt caps, and bevel joins, and stores the shape in `ThicknessProfile.variable(_:)`. `variation` is a fraction of `strokeWidth` (`0.35` stays in `[0.65, 1.35]`). `minimum` and `maximum` are multipliers of `strokeWidth`. Taper uses the existing start and end ramps and may reach 0. `pressure` is the same curve as `ThicknessProfile.pressure`, multiplied by the seeded wobble. The same `seed` repeats the wobble. An open variable marker fills with the winding rule so the two rough passes union into one mark. `BrushProfile.marker` and `marker()` with default arguments stay an even width and still fill even-odd, so current marker drawings are unchanged. Closed contours still use an even width so the join does not seam.
- Ellipse and circle fills use the same jittered radii as the outline. The fill is centered in that shape, and zigzag-line clips to it instead of a separate circle. Hachure chords are centered, so a row gap is split across both sides.
- `fillPadding` (default `0`) insets every fill from the outline. Positive values shrink ellipse radii and offset polygon edges inward. Negative values grow the fill. A padding that collapses the shape draws no fill. `fillOffset` (default `.zero`) shifts the fill without moving the outline.
- Rounded-rectangle outlines draw each corner across the full quarter circle, so the arcs meet the straight sides. Corners keep a double stroke and the same seeded roughness as the other edges.
- Ellipse hachure lines are chords of the ellipse at `fillAngle`, spaced by the hachure gap measured perpendicular to the lines. A wide ellipse no longer fills a rotated copy that spills past the top and bottom and leaves the side ends empty. Cross-hatch, zigzag, dashed, dots, and zigzag-line ellipse fills use the same chords.
- Zigzag-line fill stays inside the outline. Each hachure line is a centered sawtooth (`±zigzagOffset / 2`, pitch still `2 * zigzagOffset`) clipped so peaks and ramps do not cross circles, ellipses, or polygons.

## 1.2.0

- The Swift package, library product, and module are named Sketchy. Import `Sketchy`. Public type names (`RoughView`, `RoughText`, `AnimatedRoughView`, and the rest) are unchanged. The previous module name was RoughSwiftUI.
- Drawings can be seeded with `Options.seed` so the same roughness comes back on the next render. `fillAngle` is measured from horizontal, so `0` draws flat lines and `90` draws vertical lines.
- The example catalog, README, and performance notes were rewritten. Seeded stills and GIFs live in `docs/Examples.md`. Cache and Instruments notes live in `docs/Performance.md`.
- Text alignment and offsets stay where you place them. `FullText` is drawn as text, so it is not scaled to fit the way an SVG path is.
- CI picks an available iPhone simulator. It prefers iPhone 17 Pro (not Pro Max), then iPhone 16 Pro, then any other iPhone, on the newest installed runtime.
- `AGENTS.md` and `llms.txt` describe how to work in the repo and how to call the library.
